# 2026-11-17

## 3D 战略大地图（需求：3D、大地图、触摸拖动、点英雄弹面板、点地图行军）

**做了什么**

- 新增 `core/Hex3D.gd`：偏移坐标 ↔ 世界坐标（XZ 平面直接复用 `Hex.center`，平面 y 映射为世界 z）、
  六棱柱 / 面片 / 描边 / 单边几何生成（SurfaceTool + 顶点色）、地图包围盒、格子内伪随机散布。
- 新增 `views/World3DView.gd`（约 950 行）：
  - `SubViewportContainer(stretch) + SubViewport + Node3D` 渲染三层：地形（一个合批 ArrayMesh）、
    道具（MultiMesh：树/山/沼泽）、物件（城镇/矿场/营地/宝箱组合几何体 + Label3D 名牌）、英雄节点。
  - 相机：斜俯视（pitch 56°），`focus/dist` 双目标平滑；拖动把像素位移换算成地面位移并夹在地图范围内。
  - 输入：ScreenTouch/Drag 与 Mouse 并行，`device == -1` 过滤“触摸模拟鼠标”事件；单指拖动、
    双指捏合、滚轮缩放、tap 阈值（<14px & <700ms）区分拖动与点击。
  - 交互：点英雄 → 底部面板（Tween 滑入，宽度给足/高度由内容决定）；点地面 → `Game.reachable`
    校验 → `Game.path_to` 取路径 → `Game.move_hero` → 沿路点逐格行走。
  - 刷新：用「地形数 + explored 数 + visible 数 + 英雄坐标」做迷雾签名，签名不变就只重建高亮/物件。
- `Main.gd`：`"world"` 路由到 `World3DView`，原二维地图保留为 `"world2d"`。
- `Game.gd`：地图 16×11 → 26×17，地物重排（12 矿 / 7 营地 / 6 宝箱 / 4 城 / 5 条古道），
  开局预探索主城周边 6 格，`VISION` 3→4，`objective()` 计数改为动态。
- `tools/capture3d.gd`：开窗渲染 + 5 张截图 + 端到端验收（坐标往返、屏幕拾取、行军、拖动缩放、进战斗）。

**踩到的坑（都已写进 README 六）**

- `ConeMesh` 在 Godot 4 不存在 → `CylinderMesh(top_radius=0)`。
- 新增 `class_name` 后必须 `--import` 刷新全局类缓存，否则 `--script` 运行时报 “not declared”。
- `Label3D` 默认投影 → 文字影子像重影，必须 `cast_shadow = OFF`。
- 面板固定高度会裁内容；`reset_size()` 前设过宽度、且内容里有 `AUTOWRAP` 标签时，最小高度会被
  算成异常大值（465px）且不再回缩 → 长标签一律 `AUTOWRAP_OFF`。
- 重建子节点只 `queue_free()` 不 `remove_child()` 会叠一帧旧模型。
- 窗口被遮挡时 Godot 不绘制，截图脚本必须 `RenderingServer.force_draw(true)`，否则多张截图字节相同。

**约定**

- 三维只用一套六边形数学，`Hex3D` 反向换算必须与 `Hex` 严格对齐（selftest 有 0 错格断言）。

## 第二轮：查看/指令分离 + 3D 战场（用户要求）

**需求原话**：点任何东西都是查看界面，查看时点空白关闭；移动用鼠标右键；触摸没有右键，
按住拖动是移动、点击是查看；战斗场景也要 3D、要更大，操作逻辑和地图一样。

**落地**

- 新增 `core/View3DCtrl.gd`（基类）：SubViewport + 相机 + 手势状态机 + 底部面板 + 3D 几何工具。
  - `on_tap` = 查看，`on_command` = 指令，`on_hover` / `on_command_hover` = 悬停与拖动目标预览。
  - 触摸：单指拖动 ≥8px 进入「指令」并实时高亮目标，松手执行；双指拖动平移 + 捏合缩放；
    桌面：左键点击查看、左键拖动平移、右键指令、滚轮缩放。
  - 双指用过一次后 `multi` 标记本次手势，结束时不触发查看/指令（防止缩放收尾误下指令）。
- `World3DView` 改为继承基类，新增 4 种查看面板：英雄 / 城镇 / 矿场 / 营地 / 宝箱；
  点空地关闭面板；行军走 `move_to_cell()`，右键与拖动都汇到这一个入口。
- `BattleView` 改为继承基类，战场 13×9 → **20×13**：三维棋盘 + 部署区染色 + 岩石障碍 +
  3D 部队棋子（血量条 / 名称 / 行动金环），右侧 312px 留给行动顺序/法术/战报面板（三维视口缩到左侧）。
  **规则函数原样保留**，只换渲染与命中测试；`stacks/order/alive_count/auto_battle` 等 API 不变，selftest 直接复用。
- `Main.gd` 不变（`battle` 仍指向 `BattleView`，`world` 指向 `World3DView`，`world2d` 保留旧二维地图）。

**这轮踩的坑**

- 基类里的手指导字典别叫 `active`：`BattleView` 的「当前行动单位」也叫 `active`，继承直接冲突 → 改名 `pointers`。
- 面板滑动动画：先关后立刻开时，上一条关闭动画的收尾回调用 `visible=false` 把新面板干掉 →
  每次布局前 `kill()` 旧 tween，回调里复查 `sheet_shown`。
- `PanelContainer` 的最小高度晚一拍才准 → 监听 `resized` 把底边重新贴住屏幕（`_pin_sheet_bottom`）。
- 战场视口若满屏，右侧面板会压住单位 → `SubViewportContainer.offset_right = -312`，三维只占左侧。
- 战场高亮别用青色（部署区本来就是青/蓝），低对比看不见 → 统一暖金色。

**当前约定**

- 所有「左键/点击」只做查看，所有「右键/按住拖动」才改变游戏状态；新增交互必须遵守这条。
- 大地图与战场共用 `View3DCtrl`，不要再往各自文件里写相机/手势代码。

## 第三轮：多存档 + 创建英雄

**需求原话**：增加存档功能、支持多份存档；主界面显示存档列表；和创建英雄的界面；
创建英雄就是一份存档；创建英雄需要输入英雄名字。

**落地**

- 新增 `autoload/Saves.gd`（注册在 project.godot，排在 Game 之后）：
  - 目录 `user://saves/<id>.sav`，内容 `var_to_str({meta, state})`。
  - `snapshot()` 从 Game 抓状态；`meta_from_state()` 推出英雄名/等级/天数/城镇/矿场/兵力；
    `save_game(slot_id="")` 空 id = 新建；`load_game` / `delete_save` / `list()` / `fmt_time()`。
  - **不用 JSON**：状态里全是 `Vector2i`，`var_to_str` 原生支持，省掉坐标编解码；单份约 30 KB。
- `Game.gd`：加 `save_slot`；`new_game(hero_key, hero_name := "")` 支持自定义名字；
  新增 `restore(d)`（可见格重算、`pending_battle` 清空）；`end_turn()` 末尾自动存回当前槽。
- `views/TitleView.gd` 重写成存档列表：卡片含徽记/名字/等级/天数/占领数/保存时间 + 继续/删除（二次确认），
  空状态提示 + 大按钮「创建英雄」。
- 新增 `views/CreateHeroView.gd`：8 位统帅网格（选中换边框）+ 名字 `LineEdit`（必填 ≤12 字）
  + 右侧统帅档案；切换英雄时若名字未被手动改过则跟随默认名；`_start()` → `Saves.new_game()` → `goto world`。
- `World3DView`：顶栏加 `☰` 战役菜单（保存进度 / 返回标题 / 玩法说明 / 关闭）。
- `tools/capture_ui.gd`：截空列表 / 有存档列表 / 创建界面 / 战役菜单，跑完自动删测试存档。
- `tools/selftest.gd` 第 8 步：存档→列目录→改状态→读回→自动存档→删除，全部断言通过。

**踩到的坑**

- 存档里 `tiles/explored` 是「String 键、字典值」，`var_to_str` 没问题；但读回来后要 `duplicate(true)`，
  否则运行期 `erase()` 会改到解析结果。
- `Dict` 取值是 Variant，`var on := k == key` 会报“无法推断类型”，需显式 `: bool`。
- Windows 下 `user://` 目录名会把项目名里的冒号换成横杠：`Dota Heroes- 冰封王座`。

**待办/可扩展**

- 存档缩略图、导出/导入存档文件、独立「自动存档」续战槽。

## 第四轮：战斗手感重做（动画 + 选人 + 普攻/4技能/CD）

**需求原话**：战斗粗糙，移动直接闪现、攻击没有扣血动画；希望战斗是「选一个角色 → 出现可移动区域 →
右键移动」，并且「选中角色后面板出现普攻和 4 个技能，点技能再点目标/区域释放，技能有 CD，CD 没到按钮灰色」。

**落地**

- `DB.gd` 新增 `UNIT_SKILL_SETS`（5 种定位 × 4 技能）、`UNIT_SKILLS`（20 个技能：mult/radius/range/cd/slow/mana）、
  `unit_archetype()` / `unit_skills()`。定位规则：飞行/冲锋/龙息→assault，远程且 tier≥3 且 atk≤7→caster，
  远程→ranged，tier≥4 且 def≥7→heavy，其余 melee。
- `BattleView` 交互改成：点我方单位→`select_unit()`（出现 reach + 底部「普攻 + 4 技能」）；
  右键/拖动→`_do_move()`；`arm_skill()` 点亮→点/右键目标→`use_pending()` 分发到 `_use_attack` / `_use_skill` / `_cast_hero_spell`。
- 回合制：`next_turn()` 遇到我方槽位时不再锁定单位，只进入「玩家可行动」状态，玩家自由挑未行动的单位。
- 动画：`move_along()` 逐格 Tween（0.12s/格，`anim_lock` 锁输入）、`_strike()` 近战前冲/远程弹丸、
  `_hit_fx()` 爆裂光球 + 伤害飘字 + 受击挤压、血条 `unit_hp_frac` 目标值在 `_process` 里 7/s 追赶、
  `_die()` 缩小旋转沉没。AI 走位与攻击同样 await 动画。
- `tools/capture_battle.gd`：状态机式验收（等 AI 回合结束再操作），截图 `shot_b_*.png`；
  `tools/crop.gd` 保留下来做局部放大排查。

**踩的坑**

- `arm_skill` 存裸 id，`use_pending` 认 `skill:` 前缀 → 技能点了没反应；统一 key 后修复。
- `trait` 是 GDScript 4.7 保留字，`var trait` 解析直接失败。
- `_make_unit` 里我给血条赋初值时把 `unit_hp_frac[idx]` 的赋值一起替换掉了，导致 `_make_unit` 抛错、
  返回 null、后续 `node.visible` 崩一串；改回先算 `frac` 再写。
- 验收脚本不能写死帧号：AI 回合耗时不定，必须轮询 `busy/anim_lock/player_can_act`；
  另外测试里把敌人数量调大后我方正会被打死导致战斗提前结束，测试前要两边兵力都调平。
- 棋子标签在相邻格会互相压叠：只给选中/查看中的单位显示「名称 ×N」，其余只显示 `×N`。
- `Label3D` 伤害飘字要 `cast_shadow = OFF`，否则影子像重影。

**当前约定**

- 战斗里所有动画都走 `await` 的 Tween，规则结算仍在同步函数里完成（视觉滞后、逻辑即时）。
- 技能的 key 只有三种：`attack` / `skill:<id>` / `spell:<id>`，新增技能必须遵守。
