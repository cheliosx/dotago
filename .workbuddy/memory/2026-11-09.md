# 2026-11-09

## 从零搭建 Godot 4.7.2 游戏原型「Dota Heroes · 冰封王座」
- 目标：Dota1 题材的《英雄无敌》式回合制 4X + 六边形战棋 + 英雄 RPG，面向 iPad 横屏触控。
- 技术选型：全 GDScript、UI 全部由代码构建（无 .tscn 复杂场景树），一个 `Main.tscn` 根 + 6 个 View 类；
  六边形采用 odd-r 偏移坐标，`Hex.gd` 统一大地图与战场数学。
- 架构：autoload `Game.gd`（状态/寻路/回合/AI/结算）、`class_name DB`（静态数据表）、
  `class_name UI`（皮肤与控件工厂）、`class_name Hex`。视图通过 `Game.goto_view` 信号切换。
- 内容：8 英雄 / 16 兵种 / 9 法术 / 7 技能 / 13 装备 / 9 建筑 / 6 世界观词条。
- 美术：纯代码绘制暗黑奇幻 UI + 程序化噪点/暗角 PNG（`tools/gen_textures.py`，纯标准库）；
  内嵌 Noto Sans SC (OFL) 解决中文方块字，移除了 SimHei 以避免字体授权问题。
- 关键坑：Godot 的 `:=` 从 Variant 推断会「warning treated as error」；`max()` 返回 Variant，用 `maxi()`。
  `UI.label` 默认 autowrap 会让 HBox 里的短标签被挤成竖排 —— 改为仅 >24 字符才换行。
  `--script` 模式下 autoload 名不是编译期全局标识符，测试脚本要用 `root.get_node("/root/Game")`。
  `pending_battle` 必须**浅拷贝**，否则 `ref` 指向副本导致占领矿场/城镇结算失效。
- 验证：`--headless --editor --quit` 全脚本零编译错误；`tools/selftest.gd` 全链路通过；
  真实 OpenGL 渲染 90 帧无报错；`tools/capture.gd` 生成三张截图并人工核对布局。
- 结论：Windows 只能开发/桌面测试，iOS(.ipa) 导出必须 macOS + Xcode + 开发者账号，已在 README 说明。

## 修复：六边形图层绘制错位（用户截图反馈）
- 症状：地形色块越过金色网格线、矿场/城镇图标飘出格子，越靠地图右下越明显。
- 根因：`Hex.polygon(c, size)` 用同一个 size 同时算 `center(c,size)` 与顶点半径；
  各图层为了留缝隙传入 `size - shrink`（地形 0.8 / 高亮 2.0），于是**中心也按不同比例缩放**，
  远端格子中心偏差可达数十像素；物件图标用的是原始 `center(c, hex_size)`，三者互不对齐。
- 修复：`polygon(c, size, shrink = 0)`，中心恒用 `center(c, size)`，只把半径改为 `size - shrink`；
  `WorldView.WorldMap.poly()` 与 `BattleView.BattleBoard.poly()` 同步改调用。
  `Main.gd` 背景暗纹 `Hex.polygon(c, 30.0)` 因默认 shrink=0 保持兼容。
- 回归防护：`tools/selftest.gd` 加入同心误差断言，比较 (15,10) 格在 shrink 0.8/2.0 下的
  多边形中心与 `Hex.center` 距离，必须为 0。
- 顺带优化：矿场/营地/宝箱长名称改为悬停浮层显示（`WorldMap._draw` 末尾 `txt_bg`），
  消除相邻格文字压叠；城镇名保留。战场与大地图重新截图确认全部对齐。
