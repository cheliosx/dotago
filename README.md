# Dota Heroes · 冰封王座

基于 **Godot 4.7.2** 的回合制 4X 策略 + 战棋 RPG 可玩原型。
世界、英雄、兵种、法术与装备取材自 Dota1；美术与叙事基调为暗黑奇幻（魔兽争霸 / 魔兽世界式）。
**战略大地图与战场都是三维的**：左键/点按查看物件，右键/按住拖动下指令，双指拖动平移、捏合缩放。
城镇与英雄面板仍是二维界面。面向 iPad 横屏的触控操作设计，桌面端鼠标右键承担「下指令」。
**一份存档 = 一位自己命名的英雄 + 其战役进度**：主界面就是存档列表，创建英雄即新开存档。

> 这是个人原型，Dota 相关名称与设定归 Valve / Blizzard 所有，仅用于非商业学习与演示；正式发布需替换自有 IP 内容。

## 二、操作

| 场景 | 操作 |
| --- | --- |
| 大地图（3D） | **左键点击 / 单指点按** = 查看：英雄 / 城镇 / 矿场 / 野怪营地 / 宝箱 的底部信息面板；**点空白处**关闭面板<br>**右键点击 / 单指按住拖动** = 行军：寻路走过去（消耗移动力，抵达后自动占领 / 开战），拖动时橙色框实时显示目标格<br>**左键拖动（桌面）/ 双指拖动** = 平移，**滚轮 / 双指捏合** = 缩放 |
| 顶栏 | `－` `＋` 缩放、`◎` 视角回到当前英雄、`☰` 战役菜单（存档 / 返回标题 / 玩法说明）、`城镇` `图鉴` `英雄` `结束回合 ▶` |
| 存档 | 主界面列出所有存档（英雄名 / 等级 / 天数 / 占领数 / 保存时间 / 继续 / 删除）；`创建英雄` 里选统帅 + 输名字即新建一局并存盘；每结束一个回合自动存档 |
| 战场（3D） | **点击我方单位**选中（脚下出现金色可移动区域、底部弹出「普攻 + 主动技能 + 被动」栏）→ **右键 / 按住拖动** 移动（移动即结束行动）→ 或点「普攻 / 主动技能」点亮，**地上立刻铺出能打到的范围**，再点目标释放；点敌方单位查看情报 |
| 战场规则 | **一次行动只做一件事：移动 或 攻击**（不能移动后再打）；普攻无冷却但会被反击，主动技能 2 回合冷却且不触发反击；被动开局永久加成 |
| RPG | 英雄面板可加技能点、穿脱装备、查看法术书；城镇可建造、募兵、招英雄、买装备、换资源 |

**胜利条件**：占领天灾军团全部城镇并击败其所有英雄。

## 三、已实现的系统

### 存档（多份，本地文件）
- 主界面 = 存档列表：每份卡片显示英雄名、等级、第几天、城镇 / 矿场数、兵力、保存时间，可继续或删除（二次确认）
- 创建英雄 = 新存档：8 位统帅任选 + 自定义英雄名（必填，≤12 字），创建后立刻落盘并进入大地图
- 序列化用 `var_to_str()` 而非 JSON——它原生支持 `Vector2i` 等类型，省掉整套坐标编解码
- 落盘时机：结束回合自动保存、`☰` 菜单手动保存、返回标题前保存
- 存档文件在 `user://saves/<id>.sav`（Windows 实际路径 `%APPDATA%\Godot\app_userdata\Dota Heroes- 冰封王座\saves`），
  单份约 30 KB；战斗态不入档，载入后视野按当前位置重算

### 战略层（4X，回合结算）
- 26×17 六边形世界地图（odd-r 偏移坐标）、7 种地形与不同移动消耗、战争迷雾（已探索 / 当前可见两级）
- 统一的查看 / 指令交互：点物件看情报，右键或按住拖动了才行动，避免误触直接开战
- **三维呈现**：地形按类型抬升成六棱柱地壳，树木 / 山岩 / 沼泽用 MultiMesh 批量实例化，
  城镇 / 矿场 / 野怪营地 / 宝箱是组合几何体 + 汉字名牌；镜头可平移缩放并被夹在地图边界内
- Dijkstra 移动力范围高亮与路径回溯；英雄每日移动力由「后勤学」与靴子类装备加成
- 12 座矿场（金币 / 木材 / 秘银 / 水晶 / 灵魂精华）、4 座城镇、7 处野怪营地、6 处宝箱
- 9 种建筑：城镇大厅、兵营、射手营地、魔法塔、酒馆、铁匠铺、市场、城墙、资源仓库
- 每日收入结算、魔法值回复、每 3 天随机剧情事件、AI 英雄抢矿与袭扰补给线、胜负判定

### 战斗层（六边形战棋）
- **20×13 三维战场**：双方部署区（左蓝右红）各 7 个阵位、中央岩石障碍、单位棋子带血条与数量牌
- 按兵种**速度**排序的行动顺序；轮到玩家时可自由选择任一未行动的我方单位（不再被队列锁死）
- **每个兵种 = 普攻 + 1 主动技能 + 1 被动**：主动按定位分配（猛击 / 精准射击 / 奥术冲击 / 碾压 / 冲锋），
  2 回合冷却、不触发反击；被动（坚韧 / 鹰眼 / 法能 / 铁壁 / 迅捷）开局永久加攻击或防御或速度
- **点亮技能就看得到射程**：所有「能打到」的格子铺橙红底 + 描边，选中单位金环做呼吸放大，
  按钮同时变成高亮并显示「◆ 技能名 · 选目标」
- **一次行动只能移动或攻击**：移动动画播完直接结束该单位行动；AI 同样受这条约束（不再移动后追击）
- **战斗动画**：逐格行走（每格 0.12s 平滑位移 + 轻微起伏）、近战前冲回位、远程飞行弹道、
  受击爆裂光效 + 伤害飘字（`-224`）、血条平滑追赶、阵亡缩小沉没
- 可移动格金色高亮、敌军红环标记、范围技能悬停预览；行动顺序 / 英雄法术 / 战报浮在右侧
- 近战、远程（贴身伤害减半）、伤害随部队数量与英雄攻防结算、顶部单位血量池模型
- 英雄作为指挥官：每回合可施放 1 次法术（冰霜新星 / 龙破斩 / 神灭斩 / 奥术弹 / 神圣之光 / 霜甲术 / 死亡脉冲 / 影压 / 法力损毁）
- 敌方 AI 自动寻敌、走位与射击；`自动战斗` 可一键快速结算（适合 iPad 上碎片时间）
- 战后经验、战利品、装备掉落、部队战损与城镇 / 矿场归属结算

### RPG 与叙事
- 8 名 Dota1 英雄（水晶室女、敌法师、月之骑士、秀逗魔导师、骷髅王、影魔、巫妖、斧王），16 种兵种
- 等级 / 经验 / 攻防力量知识四维 / 7 种可升级技能 / 6 格装备栏 / 13 件 Dota 装备 / 法术书 / 酒馆招募第二英雄
- 序章叙事、6 条世界观词条、英雄传记、战役日志、战术手册

### 美术
- 大地图全程序化三维：六棱柱地壳（顶点色一次性合批）、MultiMesh 植被与山岩、组合几何体建筑与名牌
- 全代码绘制的暗黑奇幻 UI（石纹面板、金边、六角暗纹、世界之树与冰封王座剪影、星尘、颗粒噪点与暗角贴图）
- 内嵌 **Noto Sans SC**（OFL 授权）中文字体，避免中文显示为方块；三维名牌同样使用该字体
- `canvas_items + expand` 自适应缩放，触控与鼠标通用，按钮尺寸适配手指

## 四、导出到 iPad（重要）

Godot 的 **iOS 导出必须在 macOS + Xcode 环境完成**，Windows 上只能开发与桌面测试，无法直接产出 `.ipa`。流程：

1. 在 Godot 编辑器 `项目 → 安装导出模板`，下载对应 4.7.2 的 iOS 模板（Mac 上）。
2. `项目 → 导出 → 添加 iOS 预设`，填写 Apple Team ID / Bundle Identifier；方向选 **Landscape**，勾选需要的设备族。
3. 导出 `.xcodeproj` 后用 Xcode 签名并部署到 iPad（真机需要 Apple Developer 账号）。
4. 项目已开启 `emulate_mouse_from_touch`、关闭 `emulate_touch_from_mouse`，触摸手势与鼠标点击互不干扰。

## 六、修复记录

- **地图交互全部失效（打不了怪 / 占不了矿）**：`move_hero()` 先把英雄坐标设为目标格，
  再调用 `arrive()`；而 `object_at()` 把「英雄」排在查询首位，导致 `arrive()` 每次拿到的都是
  英雄自己，`mine` / `camp` / `town` / `cache` 四个分支永远进不去 —— 移动力照扣、人走上去，但没有反应，
  AI 英雄也因此从未真正占过矿。现拆出 `ground_at()` 只查地面物件，`object_at(c, exclude_hero_id)`
  支持排除站在该格上的英雄；`arrive()` 优先取地面物件，再查敌方英雄。
  `WorldView.on_map_click` 同步排除自己并调整判断顺序（己方城镇优先于切换英雄），
  点击自己所在空格则打开英雄面板。
  `tools/selftest.gd` 已加入矿场占领、宝箱拾取、营地查找回归用例；
  `tools/capture.gd` 会模拟真实点击「怪」格并验证切进战斗界面。
- **占领后看不出矿的种类**：英雄站上矿格会盖住矿图标，现于英雄图标左上角补一个角标
  （`金` / `木` / `矿` / `晶` / `魂` / `城` / `怪` / `宝`）。
- **矿场命名**：新增 `DB.MINE_NAMES`，避免「金币」+「矿」拼成「金币矿」，改为金矿 / 伐木场 /
  秘银矿脉 / 水晶矿洞 / 灵魂祭坛。
- **六边形图层错位**：`Hex.polygon` 早期把 `size` 同时用于「格子中心」和「格子半径」，
  而地形层缩进 0.8、可达高亮层缩进 2.0，导致各层中心随半径一起缩放，越靠地图右下角偏移越大，
  颜色块会越过网格线、物件图标飘出格子。现改为 `Hex.polygon(c, size, shrink)`，
  `shrink` 只缩放半径、中心恒由 `size` 决定；大地图与战场棋盘同时修复。
  `tools/selftest.gd` 已加入同心误差断言（输出必须为 `0.000000 px`）。
- **地图文字压叠**：矿场 / 野怪营地 / 宝箱的长名称原本直接画在格子下方，相邻格会互相覆盖。
  现改为只画图标与归属符号（`◆` 我方 / `▲` 敌方），完整名称在鼠标或手指悬停时以浮层显示，
  城镇名称保留。

### 技能精简 + 射程可见 + 一action一件事（本次）

- **4 技能砍成 1 主动 + 1 被动**：`DB.UNIT_SKILL_SETS` 改成 `{active, passive}`，
  只留 5 个主动（猛击 / 精准射击 / 奥术冲击 / 碾压 / 冲锋，统一 2 回合冷却）与
  5 个被动（坚韧 +2 防 / 鹰眼 +2 攻 / 法能 +3 攻 / 铁壁 +4 防 / 迅捷 +3 速），
  被动在 `make_stack()` 里直接写进 `atk_bonus` / `buff_def` / `spd_bonus`，不占操作。
  底部技能栏相应改成「普攻｜主动技能｜被动小卡（只展示）｜防御｜结束行动｜自动战斗｜撤退」。
- **点亮技能就能看见射程**：`build_overlay()` 里按 `_pending_range()`（普攻取兵种射程，
  技能取技能表里的 range）把半径内所有格子铺橙红底并描边，一次看清能打哪；
  同时选中单位的金环做呼吸式放大（`_process` 里按 sin 缩放），按钮切成高亮样式 + “◆ 技能名 · 选目标”。
- **一次行动只做一件事**：`_do_move()` 播完逐格动画直接 `end_action()`，
  不再“走完还能打”；普攻/技能在移动后自然不可用。AI 也改成同一规则：够得着就打，
  够不着就只移动，不再移动后追击（否则对玩家不公平）。
- **踩坑**：`arm_skill()` 之前存 `skill:<id>`、按钮判断用的也是同一套 key，砍技能时
  顺手把 `_pending_range()` 的字符串判断一起改了，否则点亮后算不出射程（返回 0，地面不铺范围）。

### 战斗手感重做：选人、技能与动画（上一轮）

- **移动有过程了**：以前 `s.pos = c` 直接就位，视觉上是闪现。现在先用 `Hex.flood` 的代价表
  回溯出逐格路径，再用每格 0.12s 的 Tween 顺序位移（`move_along()`），期间 `anim_lock`
  锁住输入、按钮变灰，走完镜头跟到落点。AI 走位同样走这条动画（`await move_along`）。
- **攻击有反馈了**：`_strike()` 分近战/远程——近战把棋子容器向目标前冲 0.55 再弹回，
  远程发射一颗发光弹丸；命中时 `_hit_fx()` 播放爆裂光球、伤害飘字（`-224`，上浮淡出）、
  棋子受击挤压回弹；血条不是瞬间改数字，而是 `unit_hp_frac` 目标值 + `_process` 里按 7/s 追赶，
  肉眼能看到掉血过程；阵亡会缩小旋转沉入地面再隐藏。
- **操作改成「先选人，再选技能，再点目标」**：点我方单位 → 出现可移动区域 + 底部「普攻 + 4 技能」；
  右键/拖动=移动；点技能点亮后再点目标/区域释放（右键也能释放）；点空地或再点单位取消选择。
- **兵种技能表**：`DB.UNIT_SKILL_SETS` 按 5 种定位（近战/远程/法系/重甲/突击）各给 4 个技能，
  `DB.UNIT_SKILLS` 里定义 20 个技能（倍率、半径、射程、冷却、附加减速/回魔/防御）。
  每个 stack 自带 `cd` 字典，`start_round()` 里统一 -1；冷却中按钮 `disabled` 并显示 `CD n`。
- **回合制改成「我方自由选人」**：原来队列锁死当前单位，现在轮到玩家时只占一个行动名额，
  玩家可以挑任意未行动的我方单位出手，出手后标记 `acted`，速度顺序只决定敌我交替节奏。
- **坑**：`arm_skill()` 里把 `pending_skill` 存成了裸 id，而 `use_pending()` 只认 `skill:` 前缀，
  导致技能点了没反应、按钮高亮也不亮 —— 统一成 `skill:<id>` / `attack` / `spell:<id>` 三种 key。
- **坑**：`trait` 在 4.7 里是保留字，`var trait := ...` 直接解析失败，改名为 `tr`。

### 多存档 + 创建英雄（上一轮）

- **主界面改成存档列表**：原来一进来就是英雄选择页，现在先看「有哪些战役」——
  每张卡片带英雄首字徽记、名字、等级、第几天、占领城镇 / 矿场数、兵力、保存时间，
  右侧「继续 / 删除」，删除要点两次（第一次变成「再点确认」，避免手滑毁档）。
- **创建英雄 = 新存档**：新页面 `CreateHeroView`，8 位统帅任选 + 名字输入框（`LineEdit`，必填、≤12 字），
  右侧是统帅档案。切换英雄时，只要名字还没被手动改过，就自动跟着换成新英雄的默认名。
- **序列化用 `var_to_str` 而不是 JSON**：游戏状态里到处都是 `Vector2i`（坐标、地块键），
  JSON 会丢掉类型、还得手写编解码。`var_to_str` 原生支持内置类型，一份存档直接
  `store_string(var_to_str({meta, state}))`，单份约 30 KB。
- **自动存档**：`end_turn()` 末尾把当前进度写回同一份存档（`Game.save_slot`），
  另在 `☰` 菜单提供手动存档与「返回标题」。
- **读档不信任存档里的视野**：`visible_cells` 不入档，载入后按英雄与城镇位置重算，
  避免改版本后残留过期视野；`pending_battle` 也清空，保证载入后一定站在大地图上。
- **坑**：`var_to_str` 读回来的 `Dictionary` 要和运行时状态做深拷贝（`duplicate(true)`），
  否则后续 `arr.erase()` 之类会改到解析结果；另外 `Dict` 里的 `int`/`String` 取用要显式转换。

### 交互重构 + 三维战场（上一轮）

- **查看与指令分离**：原来左键就是行军，点错一格人就走过去了。现在左键/点按只负责「查看」，
  右键（桌面）或「按住拖动」（触摸，松手处即目标）才下指令；拖动过程中橙色框实时跟着手指，
  松手立刻看得到自己点了哪一格。点空地 = 关闭面板。
- **手势重排**：单指拖动从「平移镜头」改成「下指令」，平移让给双指拖动、缩放给双指捏合与滚轮。
  桌面端仍可用左键拖动平移，鼠标与触摸事件用 `device == -1` 去重，避免同一次触摸被处理两次。
- **抽出 `core/View3DCtrl.gd`**：SubViewport、相机平移缩放、手势状态机、底部信息面板、几何小工具
  全部收敛到基类，大地图与战场共用；两者的操作逻辑从此只有一份，不会再出现「地图能拖、战场不能」。
- **战斗全面三维化**：战场 13×9 → 20×13，地形改六棱柱棋盘 + 部署区染色 + 岩石障碍，
  部队变成带血条 / 名称 / 行动金环的 3D 棋子。**规则代码一行没改**（行动顺序、攻击反击、法术、
  AI、自动战斗、战后结算全部沿用），只替换渲染与命中测试。
- **战场视口右侧让位**：行动顺序 / 法术 / 战报面板固定占 312px，三维视口只占左侧剩余区域，
  单位不会被面板压住；相机距离与俯角相应调整，整块 20×13 棋盘正好落屏。
- **面板滑动动画打架**：先关面板再立刻点开另一个物件时，上一条「关闭动画」的收尾回调会把新面板
  又隐藏掉（截图里表现为面板不出现）。现在每次布局前 `kill()` 旧 tween，并在回调里复查 `sheet_shown`；
  另外 `PanelContainer` 的最小高度要等子节点重排后才准，晚一拍变高会把底边挤到屏幕外，
  改为监听 `resized` 把底边重新贴住屏幕。

### 三维大地图（上一轮）

- **中文名牌“重影”**：`Label3D` 默认会投影，文字影子落在旁边地形上，看起来像有两份字、还带偏色。
  现统一 `cast_shadow = OFF`，名牌只画一次；野怪 / 宝箱的 `怪` / `宝` 小图标与名称原本是两条独立
  名牌，斜视角下必然互相压叠，改成 `怪 · 腐化狼穴` 单条名牌。
- **英雄面板被裁掉一截**：底部面板原来写死 238px 高，内容超出一截会被切掉。现改为“宽度给足、
  高度由内容决定”：`size.x = 可用宽度 → reset_size() → 按内容高度贴底`。同时把面板里会随宽度
  折行的标签改成 `AUTOWRAP_OFF`，否则自动换行会让最小高度先被算成 465px，面板首帧撑高后收不回来。
- **迷雾里透出可走范围**：`reachable()` 不区分是否已探索，早期版本给每格都描了金边，未探索区域
  会显出一整片金色网格，等于泄漏未知地形。现只在**已探索**格上铺淡金色底，边界线只画在区域外沿
  （用边中点向外采样邻格判断），信息量更准、画面也不再噪。
- **构筑物刷新闪鬼影**：重建道具 / 物件时只 `queue_free()` 不 `remove_child()`，旧节点要到帧末才消失，
  会和新建的重叠一帧（截图上就是双份模型双份字）。现改为先摘树再释放。
- **`--script` 截图拿到旧画面**：窗口被终端遮挡时 Godot 会跳过绘制，`get_texture().get_image()`
  取到的是上一帧，5 张截图里后 3 张字节完全相同。`tools/capture3d.gd` 在截图前
  `RenderingServer.force_draw(true)` 强制出一帧。
- **地图放大到 26×17**：地物坐标全部重排（12 矿 / 7 营地 / 6 宝箱），开局额外把主城周边 6 格
  标为已探索、视野半径 3→4，避免大图上只剩脚下几格亮着。`objective()` 的矿场 / 城镇总数改为
  按 `mines.size()` / `towns.size()` 动态取，不再写死 8 / 4。
